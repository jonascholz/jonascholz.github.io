This is a personal website, mostly used as a research blog. The focus is now AI for robotics (generalist robots, robot learning); older posts are about deep learning and spiking neural networks.

The site is built with Astro (static output, deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `master`). Run `npm run dev` for a local server, `npm run build` for a production build and `npm run check` for type checking.

## Layout

- `src/content/posts/<date>-<name>/index.mdx`: one folder per blog post, with its images and videos next to it. The `permalink` in the front matter is the public URL. `draft: true` hides a post from production builds (it still shows in `npm run dev`).
- `src/content/projects/<name>/index.mdx`, `src/content/publications/*.md`: same idea for projects and publications.
- `src/pages/`: the routes (home, blog index, projects, CV at `/cv/`, lab, RSS at `/feed.xml`).
- `src/diagrams/<name>.ts`: SVG diagrams and plots, one module per figure. Shared code lives in `src/diagrams/lib/` (SVG builder, plotting panels, param store).
- `src/lib/palette.ts`: the single source of truth for variable colors, used by both equations and diagrams.
- `src/components/three/`: the MuJoCo + three.js robot demo (`RobotDemo`).

## Writing a post

When working in `src/content/posts`, the user is usually writing a blog post. He color codes his variables and draws diagrams as SVGs generated by code. Use `src/content/posts/2025-11-22-recurrent-bptt/index.mdx` as the reference for styling and conventions. The goal for supporting artifacts is consistency between blog posts and clean, centralized code: reuse and extend `src/diagrams/lib` and the palette instead of writing one-off helpers.

These components are available in every MDX file without importing them:

- `<Notice>...</Notice>`: highlighted note box.
- `<Diagram name="lif-neuron-diagram" props={{ ... }} />`: renders `src/diagrams/<name>.ts` to static SVG at build time.
- `<Param name="x" type="range|number|select|checkbox" ... />` and `<Controls>`: controls bound to page params. Diagrams that declare `params` re-render when those params change. `<Show param="..." value="..." hidden>` toggles content.
- `<Video src={clip} label="..." />`: looping silent video (use MP4 instead of GIF; `import clip from './clip.mp4'`).
- `<RobotDemo />`: the interactive MuJoCo rover.

Figures are plain `<figure id="fig:name">` with a `<Diagram>` or a Markdown image (`![alt](./image.png)`, surrounded by blank lines) and a `<figcaption>`.

MDX is JSX: close every tag (`<br />`), no HTML comments (use `{/* ... */}`), no inline `style="..."` strings, and escape `{`, `}` and `<` in prose.

## Diagrams

A diagram module exports `defineDiagram({ params?, render({ id, props, params }) })` and builds SVG with the helpers in `src/diagrams/lib/svg.ts` and `plot.ts`. Never hard-code colors: use `varColor('U')` for variables, `color('purple')` for other palette colors and the theme tokens (`ink`, `axis`, `grid`, `paper`, `nodeFill`, `muted`) so everything works in light and dark mode. Preview a single diagram at `http://localhost:4321/dev/diagram/<name>/` while `npm run dev` runs.

## References

Sometimes a post reviews a different paper. These papers are often included in the `/reference` folder.

## Math

Math is rendered at build time by MathJax (`src/lib/rehype-mathjax.ts`); nothing runs in the browser.

- **Inline math**: single `$`, e.g. `$x^2$`. Never use `$$` for inline math.
- **Display math**: `$$` on its own lines. Numbered equations use `\begin{equation} ... \label{eq:name} \end{equation}` inside the `$$` block; `align` works too and numbers each row.
- **References**: `$\eqref{eq:name}$` renders "(3)", `$\ref{eq:name}$` renders "3", both as links. Forward references work. Unknown labels and TeX errors fail the build.
- **Colors**: use the macros from `src/lib/palette.ts` (`\cU{U[t]}`, `\cWin{W_{in}}`, `\cX{...}`, `\cS{...}`, `\calpha{...}`, `\ctheta{...}`, ...). To add a variable, add it to `variables` there; the macro, CSS and diagram color are generated from it. `\textcolor{name}{...}` also works for palette color names.

## Citations

1. Define references in the post's front matter:
   ```yaml
   references:
     - id: he2015
       text: 'K. He et al., "Delving Deep into Rectifiers," <i>ICCV</i>, 2015. <a href="https://...">paper</a>'
   ```
2. Cite inline with `[@he2015]` or `[@he2015; @micheli2025]`. Numbers follow the order of the list.
3. The reference list is rendered automatically at the bottom of the post. Citing an unknown id fails the build.

## General Notes

Don't use em-dashes. Use commas or restructure your sentences. When writing in the markdown files, the math notation has to conform to the stated rules and to the style of the document. However, when replying to the user in a chat window, there is no rendering support for math.
